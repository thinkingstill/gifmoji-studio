四步，从图到表情包

  1. 01

    锁定角色

    参考图统一裁切到 1024×1024 并转 PNG，作为每一帧的视觉锚点，避免角色串味。

  2. 02

    拆解情绪节拍

    按 起势→反应→增强→爆发→延展→转折→收束→回环 分配分镜阶段，4 帧也保证有高潮帧。

  3. 03

    逐帧生成

    每帧请求都带上阶段描述和帧序号，异步任务 + 轮询进度，单帧失败可重试。

  4. 04

    合成与压缩

    FFmpeg palettegen + paletteuse 两步编码避免偏色，超体积时自动降尺寸降色。

大小与画质

240 / 320 / 480 / 640 px 正方形，帧率 4–20，单帧停留 80–1200 ms，调色板 256 / 128 / 64 色。

体积上限

设定目标体积后自动迭代压缩，并回报是否达标，不用反复试。

分镜可编辑

拖拽排序、删除崩坏帧、导入自己的图片继续合成，最多 8 帧。

模型可替换

内置混元 v3.5，另支持 OpenAI 图像、聊天式生图与自动识别；Base URL、模型、Key 都能填自己的。

微信可导入

导出 GIF 与全部分镜 ZIP，附微信自定义表情的导入路径。

有防线

自定义地址强制 HTTPS、拒绝内网与云元数据地址、不跟随重定向；平台密钥只发往官方域名。

关于这个页面

你现在看的是 GitHub Pages 托管的项目主页 —— 纯静态，只有 HTML 和 CSS。 它能展示项目，但跑不了这个应用：生图要连模型、合成要调 FFmpeg、分镜要落盘，这些都依赖 Node 后端进程。

想真正用起来，请按下面的方式在自己的机器或任意支持 Node 的容器里启动。应用本身也已经在别处部署了一份可体验的实例。

Pages 能做

  • 项目介绍与用法文档
  • CI 状态徽章
  • 截图、演示素材

Pages 做不了

  • 调用生图模型
  • 执行 FFmpeg 合成
  • 保存分镜与导出文件

本地跑起来

# 克隆并安装
git clone https://github.com/thinkingstill/gifmoji-studio.git
cd gifmoji-studio
npm install

# 需要 FFmpeg
ffmpeg -version

# 启动（可注入服务端密钥，也可以留空让使用者自填）
TOKENHUB_API_KEY=你的密钥 npm start
# → http://localhost:3000

冒烟测试不需要任何密钥：npm test 会自己拉起一个只监听 127.0.0.1 的实例， 走完「上传分镜 → FFmpeg 合成 → 下载校验」。
